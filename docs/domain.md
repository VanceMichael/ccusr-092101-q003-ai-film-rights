# 领域约定

匿名评审后端服务于两岸微电影、微视频与 AI 漫剧赛事，覆盖收件、截止冻结、
匿名副本、利益冲突排查、可解释分派、密封评分、同分复议、奖项确认与公布证据包。

## 编号与身份边界

外部主体一律使用不含真实身份信息的引用编号，时间采用带偏移量的 ISO 8601 字符串，
附件只记录受控引用（`store://`、`copy://`）或 `sha256` 摘要。

身份信息分两侧存放，评审侧不持有院校、地区、成员姓名与原片名：

- 身份侧：团队、成员、隶属与跨团队关系、合作单位、作品原始版本、评委指导与回避、
  真实"评审编号→作品"密封信封；
- 评审侧：冻结事件、匿名副本 `RV-xxxxxxxx`、轮次、席位、密封评分、复议、奖项与证据包。

两侧通过冻结副本的外键与密封信封间接对应；读取真实映射需要秘书处与审计员双人令牌，
且开启即写审计日志。

## 匿名化

截止冻结时对当前参评版本生成独立脱敏副本：原片名整段替换，邮箱 / 手机号 /
片尾署名行 / 院校名称按模式遮蔽，文件元数据中的院校、地区、团队、姓名、联系方式、
单位等语义键整键剔除。脱敏报告 `scrub_report` 只保存命中类别与计数，不保存被遮蔽原文。

## 利益冲突

- 直接冲突：评委指导或主动回避该团队 / 作品 / 成员，或评委关联单位命中团队合作单位；
- 间接冲突：团队间合作关系与共享跨团队成员构成无向图，评委锚点团队与投稿团队
  在同一关系闭包内（按图上距离区分直接 / 间接）。

## 可解释分派与最小重排

分派须同时满足作品类别与评委专长、零直接 / 间接冲突、单评委负载上限，并尽量让每件
作品达到法定人数；按最紧约束优先、负载最低优先。每个 (作品, 评委) 组合都保留
`assigned / conflict / no_expertise / at_capacity` 结论与原因。

评委回避、超时、副本泄露只新建受影响席位：旧席位置 `reassigned` 并保留事件链，
泄露时看过旧副本的评委全部退出新副本，已密封评分永不修改。

## 密封、分权与证据

`scores`、`tie_votes`、`audit_log` 只追加（数据库触发器禁止改删），评分与审计各自
维护哈希链。评分在作品达到法定人数前彼此不可见。同分复议投票、奖项提名、奖项确认
与公布由不同权限角色完成。

每个公布奖项对应一份证据包：冻结版本摘要、有效评分集合、冲突排除记录、席位替补史、
复议裁决与时间线，并带可独立重算的 `package_hash`。

申诉核查只返回被申诉作品的资格、分派与计分材料，评委以公开指纹出现，
其他作品与匿名评委身份不可借此获知；每次查看均留痕。

业务事件需要携带来源与序列号，后续实现应保留来源系统对事实的责任边界。
