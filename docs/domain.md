# 领域约定

创作团队、素材许可、作品版本、署名份额与展映确认需要彼此对应。

外部主体一律使用不含真实身份信息的引用编号，时间采用带偏移量的 ISO 8601 字符串，附件只记录受控引用或 `sha256` 摘要。业务事件需要携带来源与序列号，后续实现应保留来源系统对事实的责任边界。

## 匿名评审约定

- **身份隔离**：投稿、团队、单位等身份信息只出现在管理端表（`submissions`、`work_members`、`judges`）；评委侧只接触 `ANON-` 匿名编号与脱敏副本摘要，匿名映射不出服务端。
- **冲突派生**：`conflicts` 表同时保存评委申报（`declared`）与系统派生（`derived`）记录；派生规则覆盖同单位、团队成员、指导/合作经历（直接）以及经由共同成员的两跳关联（间接），每次分派前重算并留痕。
- **席位与重排**：分派以席位（`seats`）为单位，回避、超时、泄露只改变对应席位状态并补一个新席位；被替换席位的评分保持密封存档但不计入有效评分集合。
- **密封与不可改**：`scores` 与 `audit_log` 由触发器保证只增不改；评分内容连同席位、作品、评委编号与时间一起计算 `score_hash`，供事后核验。
- **可验证奖项**：奖项记录固化 `frozen_hash`（冻结版本）、`score_set_hash`（有效评分集合）与 `exclusion_hash`（冲突排除记录，评委编号以摘要代替），三者均可独立复算。
- **审计链**：`audit_log` 每条记录包含前一条的摘要，任何篡改都会破坏链条并被 `/audit/verify` 检出。
